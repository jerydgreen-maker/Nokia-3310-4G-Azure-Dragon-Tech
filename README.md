# RetroShell

### One board. Different shells. Different purposes.

RetroShell is an experimental modular electronics project inspired by classic mobile phones.

The vision is to develop a reusable electronics platform built around an ESP32 and an ATmega microcontroller, designed to fit inside retro-inspired enclosures and support different applications through firmware and external peripherals.

The first hardware prototype is inspired by the Nokia 3310.

**The long-term goal is to turn a retro phone form factor into a versatile, modular electronics platform.**

## The idea

RetroShell explores using one core PCB across different enclosures and applications, rather than designing a completely new board for every device.

Potential future applications include retro-inspired portable electronics, embedded systems experimentation, robotics and control systems, portable development tools, and custom electronics experiments. These are goals, not verified capabilities.

## The vision: a family of devices

The initial concept is inspired by the Nokia 3310, with possible future enclosure adaptations inspired by the Nokia 3210, Nokia 3510 and Nokia 3510i. The project may also explore custom enclosures.

Compatibility with these models has not yet been tested or confirmed.

## Hardware concept

The planned platform uses an ESP32, an ATmega microcontroller, external peripherals connected through accessible expansion connections, a reusable core PCB, and custom or adapted enclosures.

Final capabilities depend on hardware validation, firmware development, connected peripherals and the requirements of each application.

## Current status

**Development stage: Pre-prototype**

The first physical PCB has not yet been manufactured and validated. Firmware is not ready for release. The immediate priority is to manufacture a prototype and begin hardware testing.

Initial validation will include inspecting the manufactured PCB, checking power rails and electrical connections, testing the ESP32 and ATmega, verifying programming/debugging access, testing peripheral interfaces, and documenting issues and possible revisions.
